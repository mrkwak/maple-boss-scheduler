# 계획서 — maple-boss-scheduler

작성일: 2026-10-08 · 갱신: 2026-10-08 (헥사 환산·보스 배율 기준, maplescouter 허락 가정) · 상태: 초안

표기 규칙: **[확인됨]** 출처 또는 코드로 검증 / **[미확인]** 검증 안 됨, 구현 전 확인 필수 / **[가정]** 설계상 임시로 둔 값

---

## 1. 배경과 목표

- 지인 그룹이 메이플스토리(KMS) 주간 보스를 같이 잡는다.
- 사람마다 키우는 캐릭터 수가 다르다(1개 ~ 여러 개).
- **비슷한 스펙의 캐릭터끼리** 파티를 짜야 하고, **시간 약속**도 잡아야 한다.
- 선호 패턴: 한 캐릭터가 비슷한 난이도 보스 여러 개를 **같은 상대 캐릭터와 연속으로** 진행.
  - 예) 내 A캐릭 + 지인 B캐릭 → `익스트림 스우 → 노말 흉성 → 노말 카링`

### 목표
1. 캐릭터 등록 + 헥사 환산·보스 배율 자동(최초 등록 시 1회, maplescouter 허락 가정 — ADR-0002) + 기본정보 자동(넥슨 Open API)
2. 캐릭터별 주간 보스 목표 체크 (월간 보스는 별도 주기)
3. **보스 코스(체인)** 단위로 파티 구성 + 추천
4. **보스 배율(%)로 캐릭터 줄 세우기**, 파티 배율로 묶기 (ADR-0009)
5. 주차별 가능 시간 기반 약속 시간 결정
6. 주간 진행 현황(클리어 체크) 공유

### 비목표 (1차 범위 밖)
- 결정석 수익 계산, 보스 보상 정보
- 디스코드 봇, 로그인
- 메이플스카우터 계산 공식 자체 구현, 허락 없는 maplescouter 자동 수집 (약관 금지 — ADR-0002)

## 2. 접근·사용자 식별 (ADR-0008)

- **링크를 가진 사람만** 접근한다. 로그인 없음.
  - URL에 비밀 토큰 포함 (예: `/?k=<랜덤 문자열>`), 서버(미들웨어)에서 환경변수 `ACCESS_KEY`와 비교. 불일치 시 404.
  - 링크가 새면 `ACCESS_KEY`를 바꾸고 새 링크를 다시 공유.
- 처음 들어오면 "나는 누구?"에서 멤버를 고르거나 새로 추가 → 브라우저(localStorage)에 기억.
- 링크를 가진 사람은 모두 읽기/쓰기 가능 (지인 약 5명 기준으로 감수). 삭제는 확인 대화상자.

## 3. 사용자 시나리오

1. **등록**: 링크 접속 → 내 이름 선택/추가 → 캐릭터 닉네임 입력 → 직업/레벨/월드 자동(넥슨 API) → 헥사 환산·보스 배율 자동 1회 조회(허락 후) / 그 전엔 직접 입력
2. **주간 목표**: 캐릭터마다 이번 주 갈 보스·난이도 체크 (지난주 설정 복사). 보스 배율로 "가능/빠듯/불가" 표시
3. **월간 목표**: 월간 보스는 별도 영역에서 이번 달 기준으로 체크
4. **코스 만들기**: "익스 스우 → 노말 흉성 → 노말 카링" 같은 코스 생성 → 캐릭터 추가 (초대·수락 절차 없음, 추가 즉시 확정)
5. **추천 받기**: 같은 보스를 목표로 하고 환산이 비슷한 다른 사람 캐릭 목록 → 바로 추가
6. **시간 정하기**: 이번 주 가능 시간(주마다 새로 입력) 히트맵 → 시간 확정
7. **공유**: 카톡/디코 복사용 텍스트
8. **진행**: 보스별 클리어 체크, 주간·월간 초기화 시 자동으로 새 주차/월 데이터 사용

## 4. 도메인 모델

```
Member (사람)                          — 이름, 메모
 ├─ Availability (주차별)              — 이번 주 가능 시간 슬롯
 └─ Character (여러 개)                — 닉네임, ocid, 직업, 레벨, 헥사 환산, 보스별 배율, 갱신시각
      └─ Goal (주차 또는 월별)         — 이 캐릭이 이번 주(월) 갈 보스·난이도 목록

Course (보스 코스 = 체인)              — 주차, 시작 일시, 메모, 상태
 ├─ CourseStep (순서 있음)             — 보스·난이도, 순서, 클리어 여부
 └─ CourseMember                       — 이 코스에 고정으로 들어가는 캐릭터들 (상태 없음, 추가 = 확정)

BossCut (컷표, 사용자 설정)            — 보스·난이도 → 솔로 100% 기준 헥사 환산 (배율 없을 때 환산용)
```

핵심 규칙
- 코스 안의 모든 보스는 **같은 캐릭터 조합**으로 간다 → 파티는 Step이 아니라 **Course에 붙는다**.
- 같은 사람의 캐릭터는 한 코스에 둘 이상 들어갈 수 없다(동시에 두 캐릭 조작 불가). [가정 — 사용자 확인 필요]
- 한 사람은 같은 시간대에 두 코스에 있을 수 없다 (시간 충돌 경고).
- 한 캐릭터가 같은 주차(월간 보스는 같은 달)에 같은 보스를 두 코스에서 중복 진행할 수 없다.
- 코스 최대 인원 = 코스 안 보스들의 최대 파티 인원 중 **최솟값**. [미확인 — 값 확인 필요]
- 캐릭터의 ocid는 닉네임이 바뀌어도 유지된다 [사용자 확인] → 캐릭터 식별은 ocid 기준, 닉네임은 표시용으로 갱신.

## 5. 데이터 저장소 (ADR-0007)

**Google 스프레드시트 1개**를 DB로 사용 (무료, 직접 열어서 보고 고칠 수 있음, 백업 = 파일 복사).
- 접근은 서버 라우트에서만, Google 서비스 계정 키로. 브라우저는 시트에 직접 접근하지 않음.
- 저장 코드는 `lib/db/` 인터페이스 뒤에 격리 → 나중에 Supabase 등으로 교체 가능.
- 호출 한도: 프로젝트당 분당 읽기 300·쓰기 300, 사용자당 분당 60 [확인됨 — Google 공식 문서]. 이용자 ~5명이라 여유. 서버에서 짧은 캐시(예: 10~30초) 적용.

시트(탭) 구성 — 첫 행은 헤더

| 탭 | 컬럼 |
|---|---|
| `members` | id, name, memo, created_at |
| `characters` | id, member_id, ocid, name, world, class, level, hexa_spec, boss_rates(JSON), spec_source, spec_updated_at, created_at |
| `goals` | id, character_id, period (주간 `2026-10-08` = 주차 시작일 / 월간 `2026-10`), boss_key (`swoo:extreme`) |
| `availability` | id(`member_id:week_start`), member_id, week_start, slots(JSON), memo |
| `courses` | id, week_start, title, start_at, memo, status, created_by, created_at |
| `course_steps` | id, course_id, step_index, boss_key, cleared |
| `course_members` | id(`course_id:character_id`), course_id, character_id |
| `boss_cuts` | id, boss_key, base_spec(솔로 100% 기준 헥사 환산), note, source, verified_at |

- 동시 수정: 트랜잭션 없음 → 행 단위 갱신 + "마지막 저장이 이김". 5명 규모라 감수.
- 실시간 반영: Realtime 대신 주기적 새로고침(폴링, 예: 30초) + 저장 직후 재조회.
- 보스 마스터(이름·난이도·최대 인원·주기)는 코드 `lib/bosses.js` (ADR-0006). 컷표는 자주 바꾸므로 시트 `boss_cuts` 탭에서 사용자가 직접 수정 (ADR-0009).

## 6. 스펙 데이터 (ADR-0002)

- 지표: **헥사 환산**(`hexa_spec`) + 그 기준 **보스별 배율 %**(`boss_rates`).
- 출처: maplescouter — 운영자 허락을 받는다는 가정으로 설계 (2026-10-08 문의 메일 작성).
  - 조회 시점: 캐릭터 최초 등록 시 1회 + 사용자가 "갱신"을 누를 때만 (쿨다운). 실시간·정기 배치 없음.
  - 조회 구현은 운영자 답변(허락·방식)을 받은 뒤. 지금 코드는 `lib/spec/provider.js`에 자리만 있음.
  - 답변 전·거절 시: 헥사 환산(필수)·보스 배율(선택) 직접 입력.
- 기본 정보(ocid·직업·레벨·월드): **넥슨 Open API** (`lib/nexon.js`, 헤더 `x-nxopen-api-key`). [경로·호출 제한은 공식 문서로 재확인 필요]
- 출처 링크와 갱신 시각 항상 표시, 14일+ 지나면 "오래됨".

## 7. 보스 배율로 줄 세우기·묶기 (ADR-0009)

벤치마킹 결과 (2026-10-08)
- **maplescouter "파티 보스컷"**: 파티원 닉네임으로 파티 전체 화력 기준 보스별 가능 여부 계산 (시너지·도핑 반영, 자체 공식).
- **커뮤니티 컷표(인벤·에펨코리아)**: "환산 N만 → 갈 수 있는 보스" 구간표, 배율 100~110% 기준 정리. 시점·직업·숙련도에 따라 차이 큼.
- **주간 보스 체크 사이트들**: 캐릭터별 주간/월간 체크 + 초기화. 월간 보스(검은 마법사)는 별도.

이 프로젝트의 방식 (`lib/rates.js`)
- 배율 = 공급자 값(`boss_rates`) 우선, 없으면 `헥사 환산 ÷ base_spec × 100` (컷표 `boss_cuts`).
- **줄 세우기**: 보스를 고르면 배율 높은 순으로 캐릭터 정렬.
- **파티 배율** = 파티원 배율 합. ≥100% 가능, ≥90% 빠듯, 미만 불가 [가정].
  - 예) 헥사 6.3만, 익스 스우 base_spec 12.6만 → 50% → 비슷한 캐릭 2명이면 100%
- **코스 판정**: 코스 모든 보스의 파티 배율 중 가장 나쁜 것 기준.

## 8. 파티 추천(매칭) 로직

입력: 기준 코스(보스 목록) + 기준 캐릭터

1. **후보 필터**
   - 이번 주 `goals`에 코스의 보스가 1개 이상 있는 캐릭터
   - 기준 캐릭터와 다른 사람(member)
   - 해당 보스를 이번 주 다른 코스에 이미 배정받지 않은 캐릭터
2. **점수**
   - 보스 겹침 비율: `|코스 보스 ∩ 후보 목표| / |코스 보스|` (가중치 높게 — "쭉 같이" 요구)
   - 스펙 근접도: 코스 보스별 `1 - |log(후보 배율 / 기준 배율)|` 를 0~1로 클램프한 평균 [가정 — 실제 데이터 보고 조정]
   - 시간 겹침: 기준 사람 가능 칸 중 후보도 가능한 비율 (이번 주)
   - 가중치: 겹침 0.5 · 스펙 0.35 · 시간 0.15 [가정] (`lib/matching.js`)
   - 환산이 오래됨(14일+)이면 감점 없이 표시만
3. **출력**: 점수순 목록 + 겹치는 보스 / 빠지는 보스 + 함께 갔을 때 코스 판정

**코스 자동 제안** (2단계 기능): 두 캐릭터의 목표 보스 교집합을 하나의 코스로 묶어 제안.

|---|---|---|
| 환산 수동 입력이 귀찮아 갱신이 안 됨 | 추천 정확도 | 입력 시각 표시·오래됨 표시, maplescouter 링크로 입력 동선 최소화 |
