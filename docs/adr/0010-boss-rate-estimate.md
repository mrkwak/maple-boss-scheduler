# ADR-0010: 보스 배율은 넥슨 API 스탯으로 역산 추정

- 상태: 제안 (2026-10-08, 사용자 제안 "자동 수집 없이 공개된 구조를 보고 역산")

## 배경
- maplescouter 허락 전에도 캐릭터마다 보스 배율이 있어야 줄 세우기·파티 묶기가 된다.
- maplescouter를 자동으로 조회하거나 내부 요청을 분석하지 않는다 (약관 제15조). 공개된 설명만 참고했다.
- 공개 설명 (웹 검색, 2026-10-08):
  - 보스 배율 = 내 스펙으로 보스에 30분 동안 넣는 딜의 비율, "섀도어 장인 30분 컷 = 100%" [출처: 아카라이브 뉴비 가이드]
  - 보스전 데미지 = 1 + 데미지% + 보스 데미지%, 최종 데미지는 곱 [출처: 나무위키 메이플스토리/스탯]
  - 방어율 보정 = 1 − 보스 방어율 × (1 − 방무). 방어율 380% 보스는 방무 73.68% 이하면 데미지 1 [출처: 나무위키 메이플스토리/스탯]
- 넥슨 API `character/stat`에 최대 스탯공격력, 데미지, 보스 몬스터 데미지, 방어율 무시, 아케인·어센틱포스, 전투력이 있음 (실제 호출로 확인)

## 결정
1. 캐릭터 등록·정보 갱신 때 넥슨 API 스탯을 `api_stats`에 저장한다.
2. 보스 딜 근사 (`lib/estimate.js`)
   `보스 딜 ≈ 최대 스탯공격력 × (1 + 데미지% + 보공%) / (1 + 데미지%) × max(0, 1 − 보스 방어율 × (1 − 방무))`
3. 보스별 기준값 = 직접 배율이 있는 캐릭터의 `보스 딜 ÷ (배율/100)`, 여러 개면 중앙값. 직접 배율은 사람이 maplescouter를 보고 입력한 값(또는 허락 후 공급자 값).
4. 추정 배율 = `보스 딜 ÷ 기준값 × 100`. 배율 출처 우선순위: 직접 > 추정 > 컷표.
5. 화면에 출처(직접/추정/컷표)를 항상 표시한다.
6. 보스 방어율(`lib/bosses.js`)은 아는 값만 넣고, 모르는 보스는 방어율 보정 없이 계산한다.

## 갱신 (2026-10-08 오후) — 렌선남아 저장 파일로 검증
- 헥사환산(380) 추정: 실제 76,918, 앱 추정 72,584 (−5.6%)
- **보스 기준값이 직업마다 다름**: 같은 보스에서 렌선남아(렌) 기준값이 집사0(아란)보다 11~15% 낮음 (예: 익스 스우 49,625 vs 57,304). maplescouter 공지의 "직업마다 체급이 다르다"와 일치
- 그래서 직업 보정 계수 추가: 같은 직업 캐릭터의 직접 배율로 `배율 × 기준값 ÷ 헥사환산` 중앙값. 직업 샘플이 없으면 1
- 남은 한계: 컷표에 없는 보스(예: 익스 칼로스)는 다른 직업 캐릭 배율로 역산된 기준값을 그대로 씀 → 직업 차이만큼 오차

## 정확도 측정 (2026-10-08, 렌선남아 저장 파일의 실제 배율 21개 대비)
- 직업별 헥사환산 추정 비율, 컷표 기준 직업 보정 → 컷표 없는 보스는 보정 반영해 역산
| 그 직업에 대해 아는 것 | 나머지 보스 평균 오차 |
|---|---|
| 헥사환산만 | 12.4% |
| 보스 배율 1개 추가 | 2.6~3.3% |
| 보스 배율 3개 추가 | 2.7% |
- 예외: 노말 발드릭스 약 30% 차이. 집사0 타일에 LV/S/F 손실 표시가 있었고, 손실이 배율에 비례하지 않는 것으로 보임 [원인 미확인]
- 헥사환산 추정(API 스탯 → 헥사환산)은 직업 샘플이 없으면 렌선남아 기준 −7.3%. 넥슨 API 스탯은 1시간 사이에도 약 2% 흔들림
- 결론: **직업마다 캐릭터 1명이라도 저장 파일(또는 보스 배율 1개)을 넣으면** 같은 직업의 다른 보스는 평균 3% 안팎

## 한계 [가정·미검증]
- 스탯공격력에 데미지%가 이미 들어 있다고 보고 보공만 더했다 — 맞는지 확인 필요
- 크리티컬, 레벨 차이, 아케인·어센틱포스 보정, 헥사 코어, 직업 차이는 반영 안 함
- 정확도는 직접 배율이 여러 캐릭터에서 쌓인 뒤 추정값과 비교해야 알 수 있다

## 결과
- (+) 한 명만 배율을 입력해도 같은 보스의 다른 캐릭터 배율이 바로 나온다
- (+) 방무 부족으로 딜이 안 들어가는 경우 0%로 나온다 (예: 방무 26.9% 캐릭터 vs 방어율 380% 보스)
- (−) 근사식이라 오차가 있음 → 출처 표시, 직접 입력이 항상 우선
