# ADR-0002: 스펙 데이터 소스 — 헥사 환산·보스 배율 + 넥슨 Open API

- 상태: 승인 (2026-10-08 2차 개정 — maplescouter 허락 가정으로 설계, 조회 구현은 답변 후)

## 배경
- 사용자 요구: 비교 지표는 maplescouter의 **헥사 환산**과 그 기준 **보스별 배율(%)**. 실시간은 아니어도 **최초 등록 시 한 번은 자동으로** 가져와야 함.
- maplescouter 확인 사항 (2026-10-08):
  - `robots.txt`: `User-agent: * / Allow: /`, Cloudflare 사용
  - **이용약관(2026-07-11 시행) 제15조**: 자동화된 수단(봇·스크립트·크롤러·스크래퍼·헤드리스 브라우저·MCP 등)으로 접근, 계산·환산 기능을 타 서비스의 데이터 소스로 사용, API 키·엔드포인트 무단 추출·재사용, 봇 차단 우회 금지 [출처: https://maplescouter.com/ko/agreement]
  - 제14조: 계산 로직·가공 데이터 무단 복제 금지
  - 연락처: `maplescouter@gmail.com` (사이트 하단 "문의하기")
- 2026-10-08 운영자에게 보낼 문의 메일 작성 (지인 5명, 인당 1~3캐릭, 출처 표기). Gmail 연결 권한 문제로 사용자가 직접 발송.

## 결정
1. **허락을 받는다는 가정으로 설계**한다 (사용자 결정, 2026-10-08).
   - 환산 공급자는 `lib/spec/provider.js`의 인터페이스 뒤에 둔다.
     ```js
     // fetchSpec(name) => { hexaSpec, bossRates: { 'swoo:extreme': 52.3, ... }, sourceUrl, fetchedAt, raw }
     ```
   - `SPEC_PROVIDER=maplescouter` 공급자는 자리만 있고, 호출하면 "조회 방식 미정" 오류를 낸다.
   - **조회 구현은 운영자 답변에서 허락과 방식(공식 API·엔드포인트·호출 제한)을 받은 뒤에 한다.** 그 전에 사이트 내부 요청을 추정해 호출하지 않는다.
2. 조회 시점 (허락 후): 캐릭터 최초 등록 시 1회 + 사용자가 "갱신"을 눌렀을 때만. 캐릭터당 쿨다운. 실시간·정기 배치 없음.
3. 답변 전·거절 시: `manual` 공급자 — 사용자가 헥사 환산(필수)과 보스 배율(선택)을 직접 입력. 배율이 없으면 컷표로 환산 (ADR-0009).
4. 기본 정보(닉네임→ocid, 직업, 레벨, 월드)는 **넥슨 Open API** (`lib/nexon.js`). ocid는 닉네임 변경 후에도 유지 (사용자 확인) → 캐릭터 식별 기준.
5. 화면에 출처(maplescouter 결과 페이지 링크)와 갱신 시각을 항상 표시. 14일+ 지나면 "오래됨".

## 갱신 (2026-10-08 오후)
- 사용자가 운영자 허락을 받았다고 알려줌: "사이트에서 수집, 보스 배율까지" (답장 원문은 아직 못 받음 — 받으면 여기에 붙일 것)
- 이 세션에서 사이트 자동 조회(브라우저 실행)는 Claude Code 자동 모드 안전 검사에 막힘 → 자동 조회 구현은 보류
- 대신 **저장 파일 가져오기**를 넣음: 사용자가 브라우저에서 효율·보스컷 페이지를 저장(Ctrl+S) → 앱에 업로드 → `lib/spec/importPage.js`가 헥사환산(380)·보스 배율 추출. 앱은 사이트에 접속하지 않음
- 자동 조회를 넣게 되면 같은 파서를 쓰고 가져오는 부분만 추가하면 됨

## 대안
- 허락 없이 자동 수집 → 약관 제15조 위반. 기각.
- 넥슨 API 전투력만 사용 → 사용자가 원하는 지표 아님.
- 환산 공식 직접 구현 → 공식 비공개, 제14조 리스크. 기각.

## 결과
- (+) 허락 여부와 관계없이 앱은 동작 (수동 입력 + 컷표 환산)
- (+) 허락 시 공급자 구현 하나만 추가하면 됨
- (−) 답변 전까지는 수동 입력
