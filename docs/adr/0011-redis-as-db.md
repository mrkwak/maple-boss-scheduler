# ADR-0011: 운영 저장소는 Upstash Redis (스프레드시트는 대안으로 유지)

- 상태: 제안 (2026-10-08) — 사용자 요구 "서비스 계정은 복잡함, 간단한 걸로"

## 배경
- ADR-0007(스프레드시트)은 Google Cloud 프로젝트·서비스 계정·키 발급·시트 공유가 필요해 설정이 번거롭다.
- 이 세션의 Vercel 연결로는 프로젝트·스토리지 생성이 403으로 막혀 있어, 사용자가 대시보드에서 직접 만들어야 한다.
  그러므로 "클릭 몇 번 + 키 복사 없음"이 기준.

## 결정
- Vercel 대시보드 Storage에서 Upstash Redis를 만들어 프로젝트에 연결한다. 연결 시 `KV_REST_API_URL`/`KV_REST_API_TOKEN`이 환경변수로 들어온다.
- `lib/db/redis.js`: 테이블마다 해시 `mbs:<테이블>`, 필드 = id, 값 = 행 JSON. Upstash REST(fetch)만 사용, 추가 패키지 없음.
- 저장소 선택 순서: Redis 접속 정보 → `SHEET_ID`(스프레드시트) → 메모리(개발).
- 보스 기준값(boss_cuts)은 저장소에 넣어야 하므로 `PUT /api/cuts` 추가 (비밀 링크 쿠키로 보호).

## 확인 못 한 것
- Upstash 무료 플랜의 현재 한도(명령 수·용량)는 공식 문서로 다시 확인하지 않았다. 5명 규모에서 문제될 가능성은 낮다고 보지만 추정이다.

## 결과
- 장점: 서비스 계정 불필요, 행 단위 쓰기라 동시 수정에 덜 깨짐.
- 단점: 데이터를 시트처럼 눈으로 보고 고치기 어렵다(Upstash 콘솔의 Data Browser로는 볼 수 있음).
