# ADR-0003: 스펙 수집은 배치 + DB 캐시

- 상태: 제안

## 배경
- 외부 사이트를 페이지 열 때마다 호출하면 느리고, 상대 사이트에 부하를 주고, 차단 위험이 크다.
- Playwright가 필요한 경우(ADR-0002 (b)) Vercel 서버리스 함수에서 돌리기 어렵다 (실행 시간·용량 제한 — 구체 수치는 미확인).

## 결정
- 환산 수집은 **GitHub Actions 스케줄 워크플로**에서 하루 1~2회 실행한다.
  - 등록된 캐릭터 목록을 Supabase에서 읽고 → 캐릭터마다 간격(예: 3~5초)을 두고 조회 → `characters.spec_*` 업데이트
  - Supabase service role 키는 GitHub Secrets에만 둔다.
- 사용자가 "지금 갱신"을 누르면 즉시 조회하지 않고 `workflow_dispatch`로 배치를 트리거하거나 갱신 요청 큐에 넣는다. 남용 방지를 위해 캐릭터당 쿨다운을 둔다.
- 넥슨 API 기본정보는 등록 시 서버 라우트로 즉시 조회 + 배치에서 함께 갱신 (30일 내 갱신 고지 반영).

## 대안
- 요청 시 실시간 조회 → 부하·차단·지연. 기각.
- 별도 서버(VPS) 운영 → 비용·관리 부담. 필요해지면 재검토.

## 결과
- (+) 상대 사이트 부하 최소, 무료 범위에서 운영 가능할 것으로 예상 (GitHub Actions 무료 한도는 리포 공개 여부에 따라 다름 — 확인 필요)
- (−) 값이 최대 반나절 정도 늦음 → 갱신 시각 표시로 보완
