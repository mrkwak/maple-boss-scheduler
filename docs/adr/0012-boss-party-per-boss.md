# ADR-0012: 신청 화면의 파티는 보스마다 따로 (보스 1개짜리 코스)

- 상태: 승인 (2026-10-08) — 사용자 결정 "보스별 파티가 나을 것 같다"

## 배경
- ADR-0004는 "파티 = 같은 멤버로 보스 여러 개(코스)"다. 실제로는 보스 2개는 2인, 2개는 3인처럼 보스마다 같이 가는 사람이 다르다.
- 한 코스에 묶으면 A와는 흉성만, B와는 카링만 겹쳐도 셋이 모든 보스를 같이 가는 것으로 저장된다.

## 결정
- 신청 화면(매칭)은 보스마다 같이 갈 사람을 고르고, **보스 1개짜리 코스**를 보스 수만큼 저장한다.
  ADR-0004의 "멤버가 다르면 코스를 나눈다"를 그대로 따른 것이라 저장 구조(테이블)는 바꾸지 않는다.
- "이번 주 일정" 화면은 같은 날·같은 시각의 코스를 묶어 보여준다(묶음은 화면 계산, 저장하지 않음).
- 같은 사람의 캐릭은 한 보스 파티에 하나만 고를 수 있다(기존 규칙 same_member).
- 같은 사람이 다른 캐릭으로 시작 시각 2시간 미만 차이의 코스에 들어가면 경고한다(`lib/conflicts.js`, 차단은 안 함).
  2시간은 [가정 — 보스 한 묶음을 2시간 안쪽으로 봄].
- 기존 코스 편집 화면(여러 보스 코스)은 고치기용으로 남긴다.

## 대안
- 코스는 그대로 두고 보스 줄마다 "빠지는 사람"을 표시: 변경은 작지만 같은 정보를 우회해서 담아 헷갈림.
- 새 테이블(보스별 파티 + 세션): 표현력은 같고 데이터 이전·API가 늘어남. 운영 데이터가 없어(코스 0개, 2026-10-08 확인) 이점이 적음.

## 결과
- (+) 어떤 인원 조합이든 표현됨. 테이블·API 변경 없음
- (−) 같은 시간 여러 보스를 한 번에 고치려면 파티마다 따로 고쳐야 함
